# Operating Model

Purpose: give Codex enough autonomy to keep producing while preserving Sathian's control over high-leverage creative decisions.

## Autonomy Defaults

Codex can proceed without pausing for approval on:

- Drafting scene copy.
- Creating storyboard revisions.
- Creating capture manifests.
- Creating prompt queues.
- Producing placeholder diagrams.
- Building Remotion/data scaffolding.
- Updating asset-slot status.
- Generating non-final variants clearly labeled v0, v1, v2.
- Replacing weak wording with stronger wording that preserves the approved strategy.

Codex should ask or wait for explicit approval on:

- Final Tanda face lock if a new reference image is supplied.
- Final submitted video links.
- Claims about live MoonPay, Solana Mobile Store, or production on-ramp availability.
- Anything involving real funds, wallet transactions, or publishing publicly.
- Replacing user-recorded voice or personal founder framing.

## Approval Granularity

Approve at the scene level, not the tiny-task level.

Good approval comments:

- "p03 is approved, make it smoother."
- "p04 is too finance-heavy, make it warmer."
- "Use this Tanda face."
- "Cut MoonPay unless it works by Friday."
- "Technical video should be more builder-led."

## Scene Status Meanings

- `outline`: strategy and copy are still open.
- `needs-assets`: scene direction is good, but footage/avatar/diagram is missing.
- `draft-ready`: assets are in place and the scene can be assembled.
- `approved`: scene should be protected unless new facts force a change.
