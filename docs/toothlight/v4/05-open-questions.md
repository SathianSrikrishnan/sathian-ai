# Toothlight V4 Open Questions

Date: 2026-05-21
Status: active decision log

## Product

1. Is a free Toothlight free forever, or only the first Toothlight per child/family?
2. Should the future letter be strongly prompted immediately after save, or primarily through the saved-memory email?
3. Should the first V4 MVP include a full parent dashboard, or a lighter "my Toothlights" shelf plus account page?
4. Should family notes require parent approval before being attached to the future reveal?
5. Should voice notes ship in MVP or as a fast follow after text letters validate demand?

## Business

1. Should V4 use the current 2% contract fee or plan a 1% future fee?
2. What is the acceptable fully loaded fee after provider, platform, and network costs?
3. Should Toothlight creation remain free even if AI generation creates real cost?
4. What deposit sizes should the product optimize around?
5. Should the provider demo support real money, sandbox money, or read-only flows first?

## Technical

1. Is account-level privacy enough for the first private-letter MVP?
2. Should future letters be application-encrypted before storage?
3. Should a hash of the letter exist on-chain for tamper evidence, while the content remains off-chain?
4. Should V4 plan for USDC/stablecoin support even if the current contract path is SOL-first?
5. How should unlock reminders and child education delivery be scheduled?

## UX

1. How visible should the locked-letter object be before unlock?
2. What visual treatment makes a Toothlight with a letter feel meaningfully richer than one without a letter?
3. Does the child-facing flow include voice prompts, or should voice appear only after parent save?
4. Should the grandparent page lead with the note composer or the gift amount selector?
5. How much of the Network/Atlas story world belongs in the main creation flow?
