# Domain Context

This file records the public-facing language used to connect Sathian's projects, site agent, and customer conversations without implying that every experiment is a finished product.

## Capability Discovery

The guided process that helps a visitor connect a problem they have with a kind of workflow Sathian has evidence he can design or build.

_Avoid:_ treating it as a catalogue of autonomous agents or a promise that a ready-made service already exists.

## Capability Pattern

A customer-readable description of a repeatable workflow shape, such as evidence-backed research or bounded automation. A capability pattern explains the problem, the useful outcome, the proof, and the limits without claiming that a standalone product is already for sale.

_Avoid:_ agent, product, service, or template when none of those is presently available.

## Proof Project

A public project, artifact, receipt, or case study that demonstrates some or all of a capability pattern.

_Avoid:_ using a proof project as evidence for behavior it does not actually demonstrate.

## Public Prototype

An incomplete, non-production system with a public evidence surface and an explicit boundary. It may show research, workflow design, or test results while private data and unfinished execution remain local.

_Avoid:_ live product, active service, submission, or customer-ready automation unless those claims are independently true.

## Boundary

The data, actions, guarantees, and operating responsibilities that a capability or project deliberately excludes, keeps private, or leaves behind human approval.

_Avoid:_ burying a boundary in fine print after a broad capability claim.

## Availability

What a visitor can truthfully do now: use a live product, inspect public evidence, request a private walkthrough, or discuss adapting a capability pattern.

_Avoid:_ ambiguous calls to action such as “try it” when the public surface is evidence rather than a usable workflow.

## Qualified Note

A deliberately submitted note in which a visitor identifies a real problem, relevant capability pattern, or reason to speak with Sathian and optionally supplies a reply address.

_Avoid:_ counting casual agent questions or curiosity clicks as customer demand.
